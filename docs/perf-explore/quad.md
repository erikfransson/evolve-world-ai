# Brain kernel: four same-shape brains per f32x4 (idea 95, "quad")

Branch `pl-quad` on perf-live ae04de2 (+512 `brain.wat`, +248 -26 `brainKernel.ts`, tests +53 -2). Exact: fingerprints equal in every case and run.
Question: does running four brains of one shape in the four lanes of each SIMD vector, all layers including the first, beat the one-brain kernel, and can the bank keep quads through births, deaths, slot reuse and thinkEvery?

## What changed
- `brain.wat` (+512, generated by `scratchpad/quad/genq.py`): `quadForward` over one 64-byte record per quad (weights, a member's descriptor for the sizes, the four lane slots, inputs and outputs, brain count). Quad weights are `[in][out][4]` per layer, bias row last, no pad4 columns. A lane runs when its slot carries this run's stamp in the mark array (moved into kernel memory); other lanes read a zero vector and write a dump, so any subset of brains runs correctly. Quads that ran only some of their brains are listed for the bank.
- First layer: `$qcompact` loads the four inputs four at a time, ORs the four `!= 0` masks into one union list (same shuffle table as `$compact`) and stores the inputs transposed, `x[i]` = the four lanes. `$qlayer0` runs the union list in ascending order; per input `nm` = sign bit in the lanes whose input is `+-0`, and each product is OR-ed with it. For finite weights `w * +-0` is `+-0`, OR-ed it is `-0`, and `acc + -0 == acc` for every acc (`+0 + -0 = +0`, `-0 + -0 = -0`, NaN stays), so each lane adds exactly its own non-zero inputs in ascending order, as `$layer` does. Brains with a non-finite weight run alone.
- Later layers `$qlayer`: dense, bias then every input in order, as `$layer` with the iota list. Output blocks of 12, 8, 6, 4, 2, 1 vectors (12 accumulators in registers). tanh in `$qtanh`, the base polynomial with constants in locals, called once per layer.
- The last layer is transposed back to the four output vectors; pad neurons get the +0 that the one-brain kernel writes there.
- `brainKernel.ts`: a brain joins the fullest quad of its shape with an idle lane, or opens a quad once three others of its shape exist; fewer run alone in the old kernel. A member's slot block holds only its input and output (same addresses for the fill and step kernels), so weights are stored once. A brain that leaves frees its lane; a quad with no brain is freed, otherwise merged into another quad of its shape with room (lane copies only, no address the creature holds changes). `forwardRun` stamps the run list, runs the lone brains (block order, unchanged), then `quadForward` over all records. Records change only when a lane does (rewritten in place) or a quad comes or goes (rebuilt), so a tick costs no JS loop over the quads: forwardRun's JS time is 0.10 ms against 0.05 ms on the base (building the records every tick cost 0.3 ms, half the kernel gain, in a first version).
- Quads listed as partly run are repacked after the run by swapping lanes until each quad runs all its brains or none. This covers thinkEvery above 1 (the thinkers recur every thinkEvery ticks, so the lanes settle) and the spare creatures that keep their brains while unused (44 of 3359 quad brains in the live bench). Without it the brain phase was 1.59x slower at `--think 2` (2.39 to 3.80 ms).
- Tests: `wasmKernels` gets a quad test (5 shapes incl. 1-layer and 26-wide, -0 first-layer biases, -0 and all-zero inputs, Infinity weights, 12 rounds of births, deaths, slot reuse and thinking subsets, every output word compared with a one-brain bank, idle slots untouched). It fails when the -0 OR is removed. `ecoPool` "frees the kernel resources": the arena top now settles from the second cycle (the spare creatures keep the shape count up, so the first cycle's three lone brains join quads afterwards), so the test compares cycles 2-4 to cycle 1.

## Memory
Weights are stored once: a member's slot block shrinks to its input and output (256 bytes), the quad block holds four brains without pad4 columns (25.0 MB of quad blocks for 3318 brains, against 25.1 MB of one-brain weights). Idle lanes cost a quarter of a quad each.

## What is left for a full version
- Quads with one or two live brains still run as quads (more work per brain than alone); a world whose shapes are spread thin (brain2.md: 4281 shapes in 9411 creatures) keeps most brains alone, so the gain there is small, not negative. Lone brains are never moved into a quad once one exists for their shape (only newborns join), so a shape converts as its brains are reborn.
- First-layer union cost grows when the four lanes' rays see different things; grouping quads by similar non-zero patterns was not tried.
- The generator lives in the scratchpad; the 492 lines of `brain.wat` are its output (12 vector blocks for the masked and the dense layer).

## Verdict suggestion
Exact and complete enough to merge after review: every bench fingerprint equal, births, deaths, slot reuse, thinkEvery and spare creatures handled, RSS unchanged. The gain is clear at the cap (brain -0.6 ms, about 5% of the tick) and small in the mixed bench (-0.2 ms, 1.5-2%, under the 2% bar there), at the cost of 760 lines, most of them generated SIMD blocks.
A further rewrite does not pay on these numbers: the remaining first-layer cost is the union of four non-zero lists (1.3-1.6x the work), and the native kernel (`nativeprod.md`, 1.55x) beats this on every case. Suggest: merge if the cap case matters (the live world sits at the cap), else park with the native kernel decision.
