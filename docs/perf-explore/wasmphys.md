Branch `wasmphys`. Alternating pairs, load average 10 to 14, noise about 3%. Switch used for the A/B: `forceJsStep` (stepKernel.ts), tests only.

- Math: `Math.sin` and `Math.cos` are imported into the module and called per creature, so rows equal the JS path on any engine. `Math.exp` is only in `decaysFor`, evaluated once per species per call in JS and written into the species block, so no import is needed. The imported calls cost little: the phase is 0.45 us per creature against 0.6 JS, the earlier inlined fdlibm kernel was 0.48 us.
- Layout: all row, call block (`P_*`) and species block (`Q_*`) offsets are in `layout.ts`, substituted into `step.wat`. Terrain constants (`CLEAR_CELL`, `ROCK_CELL`, rock tables, rasters via `Terrain.nearFor`) go in through the call block from their TS definitions.
- Twins: `stepRows` stays the reference and the fallback (`stepResident` picks), each side has a comment naming the other.
- Tests (`tests/typescript/wasmStep.test.ts`, 17): field-for-field parity per tick on 7 world kinds with perturbed creatures (walls, rock edges, extreme speeds, energies, headings), 24 randomised worlds, NaN and infinite rows, memory growth mid-tick, whole runs WASM vs JS step (4 worlds), insert plus retune mid-run, save/restore across modes both ways, RL episodes on reused kernels. Helpers 0 and 3 threads: `ecoLive.test.ts` plus the bench fingerprints.
- Red check (deliberate breaks of step.wat, regenerated): remember rate off by one unit 16 of 17 tests fail, ground factor dropped on y 9, rock bounce constant 1.0000001 3, aging ticks off by one 6, brake uses drag 11, wall limit 0.01 off 12. Dropping the clear-raster early-out passes by design: it only skips work, the full path would not move the creature.
