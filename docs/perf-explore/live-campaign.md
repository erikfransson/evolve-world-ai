# Live World speed campaign (2026-10-27)

Goal: the live server's tick (The Inland Sea, one thread, nice 19, cap 5000) runs faster without peak memory running away.
Branch `perf-live` from `development` (c384eb5). Every idea is logged below with its measured effect and verdict; kept ideas are merged into `perf-live`.

Benchmark: `node src/liveBench.ts` in `server/` (new, this campaign): the server's `LiveWorld` with `liveConfig`, seeded with the live founders, stepped headless on one thread.
Number to compare: `cpuMsPerTick` (user CPU per steady tick, after the first quarter), run as `nice -n 19 ionice -c3 chrt --idle 0`, several alternating pairs because the laptop is loaded (load 10-12).
Fingerprint equal means bit-identical results.

## Decisions for Erik
- Merge perf-live into development: ready (1.48x mixed / 1.46x cap bit-identical, six engine review rounds and the three push-gate reviews closed, full suite green, 6 h soak passed, Unreleased notes in docs/changes.md). One deferred pre-existing note: no fsync before a save's rename (a crash can leave a zero-length newest save; recovery falls back to older saves; an fsync would stall the tick thread). Nothing is pushed.
- Quad-lane brains (`pl-quad`, exact, 760 lines): brain phase 1.06x mixed / 1.20x cap, about 2-5% of the tick; worth it only if the cap case matters and the native kernel stays parked.
- bf16 genomes (`pl-bf16genome`, two switches): 1.03-1.04x only, but 12.5 MB less bank memory, 27% smaller saves and engine-exact genomes; a rule change with new pins and a fresh world. Not recommended for speed alone.
- Huge pages: measured on the brain kernel with MADV_COLLAPSE, 1.7-3.7% of the kernel (about 1% of the tick), via THP `always` system-wide (root) or a native madvise in the server; collapse fails on fragmented memory, so not guaranteed (`pagepack.md`).
- Helper threads on the server host: the engine's ThinkPool (`liveBench --threads`) was rejected in idea 6 only because this laptop runs the campaign at SCHED_IDLE under load; on a host with spare cores it is the largest untested lever (sense and brain are 70% of the tick and split across threads). Needs one measurement on the host.

- **Exact wins are merged** (1.17x at 60 s, 1.18x over 1800 s, bit-identical; peak memory over 7200 s with saves 533 MB against 751 MB on development); the branch is ready to merge into `development` (73 commits, 53 files, +2175/-149; one correctness review and the three Live push-gate reviews passed; `development` has not moved since the branch point). The exact pool is dry after 26 ideas: nothing runs outside the profiled phases (0.01 ms), and every phase has been cut or shown flat.
- **`dt` 1/20 (1.5x more, `dt20.md`; ready on `pl-dtswitch`, `dtswitch.md`: merge it and the first start begins a fresh world, old saves refused and kept): the same 1.5x as `thinkEvery` 2 with a much smaller ecology shift (turn rate +11%, food eaten identical, births within the seed spread); one line in `liveConfig`, memory rates kept, fresh world on the switch (old saves carry ticks of the old dt). 1/25 gives 1.17x for half the shift. Say which, or neither.
- **`eco.thinkEvery` 2 (1.5x more) is in the code but off in `liveConfig`.** It changes the ecology (births and deaths 1.5-1.9x, creatures turn more and eat less, from the brain's delayed self-feedback), see `think2.md`, `think3.md`, `sense2.md`. Say yes to turn it on, or no to leave it as a page option.
- **Native AVX2 kernels**: re-measured against today's kernels the brain addon is worth 1.03-1.05x per tick (`nativeprod.md`, branch `pl-nativeprod` is merge-ready and opt-in) and the sense kernel about 1.05x (`nsense.md`, prototype); together under 1.1x for a g++ build at deploy and two C++ twins to keep in step. Recommendation: no, unless the server moves to a host where the extra 5-10% matters.
- **No-viewer frame skip** (`noviewers.md`, branch `pl-noviewers`): 0.6-1.3% while nobody watches, server code under the push gate. Say yes to include it in the review round.
- **Huge pages** (two scouts): `echo always > /sys/kernel/mm/transparent_hugepage/enabled` is a root, system-wide toggle; the kernel memory then gets 2 MB pages. Unknown gain (0.5-4%), exact. Say yes to set it for a bench pair; it only helps the server if it stays set.
- **Newer Node** (untested): the server and the bench run Node 24.18 (V8 13.6), the only version installed; a newer V8 could change the wasm code, and the fingerprint would show whether Math.sin/cos/exp still agree. Say yes to install one under nvm for a bench pair.
- **Relaxed-SIMD FMA** (`fma.md`, branch `pl-fma`): 1.025x, not bit-exact across machines. Not recommended.
